# Constructor-by-constructor replay research note -- 2026-07-07

Status: informal research note. No theorem in this note is established unless mirrored
in `docs/` or Lean.

## Target requested

Upgrade the finite-domain completeness proof from a macro-rule proof

`Closes (rigidGroundConstraints n ++ groundBranch B) -> QClosesExt B`

to a publication-grade constructor-by-constructor replay of the propositional tableau
closure inside the finite-domain quantified tableau.

## Refutation-first finding

The theorem is not publication-meaningful if stated with the current `QClosesExt` as
the target, because `QClosesExt` already contains the macro constructor
`rigidPropSim`. Lean could prove the statement in one step by invoking that constructor,
but such a proof would not replay any propositional constructor.

Therefore the publication-grade target must first separate a **core** extensional
calculus from its macro rules:

- core rules: equality repair, ground-extensional closure, propositional connective
  rules, finite quantifier rules;
- excluded macro rules: `propSim` and `rigidPropSim`.

Only a theorem targeting that core calculus, or a theorem whose proof is audited not to
use the macro constructors, has the intended publication value.

## Main technical obstruction

A direct induction on an arbitrary propositional `Closes` proof does not align with
finite-domain quantified branches when quantifiers are present.

Reason: grounding finite quantifiers uses right-nested finite folds:

- `forall x phi` grounds to a finite conjunction fold;
- `exists x phi` grounds to a finite disjunction fold.

The propositional tableau can decompose such a fold one constructor at a time. After the
first decomposition step, the child branch contains a residual fold tail, for example:

`T+ foldConj [g1, g2, ..., gk]`

decomposes to

`T+ g1` and `T+ foldConj [g2, ..., gk]`.

The residual formula `foldConj [g2, ..., gk]` is not, in general, the grounding of any
single finite-domain quantified formula already present in the original branch. Thus a
replay state containing only a `QBranch` is too small: it has no object corresponding to
the residual fold tail.

This is not a soundness problem and it does not refute finite-domain completeness. It
shows that the constructor replay theorem needs an enlarged proof state.

## Viable repaired replay statements

### Candidate A: core calculus plus trace tokens

Define a replay trace whose items are either:

1. ordinary finite-domain signed formulas;
2. residual universal-fold tokens;
3. residual existential-fold tokens;
4. rigid ground atoms generated by empty fold tails or rigid equality constraints.

Then prove by induction on the propositional `Closes` derivation that every closure of
the traced propositional branch replays to a core quantified closure of the associated
`QBranch`.

This is the most literal constructor-by-constructor replay.

### Candidate B: block replay for finite folds

Keep the target as a core `QBranch`, but prove fold-block lemmas first:

- a closed propositional branch containing a signed finite conjunction fold can be
  transformed into the corresponding closed branch containing all finite instances;
- a closed propositional branch containing a signed finite disjunction fold can be
  transformed into the corresponding family of witness/branching instance branches.

Then the main replay theorem uses propositional constructors for ordinary connectives
and the block lemmas for quantifier groundings.

This is closer to the paper proof style and likely shorter than trace tokens, but less
literal than Candidate A.

## Recommendation

Use Candidate A if the goal is a fully auditable Lean theorem mirroring every
propositional constructor. Use Candidate B if the goal is a cleaner paper proof with
Lean-backed fold-block lemmas.

The next Lean step should be:

1. define `QClosesExtCore` without `propSim` and `rigidPropSim`;
2. prove `QClosesExtCore.toExt`;
3. define a replay trace type for residual fold tails;
4. prove the propositional connective cases first;
5. prove the finite fold cases;
6. state the final replay theorem targeting `QClosesExtCore`.

## 2026-07-07 arbitrary bridge refutation

The bridge target above was still too broad. Lean now verifies a counterexample.

- `replayEmptyBadTailTrace` is the trace with `qFoldConjTail T- []` followed by rigid
  constraints for domain size 1.
- It is well formed: `replayEmptyBadTailTrace_wf`.
- Its ground branch closes: `replayEmptyBadTailTrace_ground_closes`, because the empty
  conjunction tail contributes `T-(top)` and the rigid constraints contribute `T+(top)`.
- Its quantified projection is empty: `replayEmptyBadTailTrace_qBranch`.
- It cannot have a `ReplayClosesCore` certificate:
  `replayEmptyBadTailTrace_not_replayClosesCore`.
- Therefore the universal bridge
  `WF T -> Closes (ReplayTrace.groundBranch T) -> ReplayClosesCore T` is refuted by
  `arbitrary_ground_replay_bridge_refuted`.

This is a useful negative result. The next bridge must use a generated/admissible-trace
invariant that rules out bad empty-tail states, rather than only `ReplayTrace.WF`.

The second residual dispatcher family has also been eliminated:

The third residual family behaved differently. The shortcut "q-vs-fold nonmatching

## 2026-07-08 recursive q-vs-fold replay step update

The first recursive q-vs-fold replay layer is now verified.

- Non-branching signs close immediately against the head of the fold tail:
  `T+ conj` versus `T- foldConj`, `F- conj` versus `F+ foldConj`,
  `T- disj` versus `T+ foldDisj`, and `F+ disj` versus `F- foldDisj`.

## 2026-07-08 suffix-aligned tail consumer (Prop 3.72) — the consumer exists

The tail consumer is now a verified theorem, and it did NOT reuse the step lemmas by
iteration at the trace level. The step lemmas' branch-level right obligation cannot be
re-fed to the same lemmas (their ground alignment is stated against the FULL fold item
list, while after one step the invariant lives on the TAIL). The working formulation
generalizes the alignment to an arbitrary suffix of the fold's item list:

    fold item (full) in trace, q-item (S_q, rho, chi) in trace,
    suffix <:+ full, ground rho chi = fold(suffix ground forms)
    ==> core closure of the trace's quantified branch.

Proof: structural induction on chi, generalizing trace and suffix. Descent through the
matching binary connective closes the left child against the suffix head (any member of
the full tail is in the branch — Prop 3.58 was the key reuse) and recurses on the
extended trace with the suffix tail. The matching quantifier closes memberwise: equal
fold chains have equal form lists (new `foldConj_inj`/`foldDisj_inj`), so every domain
instance finds an opposite-signed, equally-grounded fold member. All other shapes are
impossible by outer-constructor clash; the empty suffix is impossible for EVERY chi, so
no admissibility hypothesis is needed anywhere.

Deliverables (all sorry-free, full build 2001 jobs, axiom-clean):
- `ReplayTrace.closeT_qFoldConjTpos_qTneg_tailConsume_core` (+ F/conj, T/disj, F/disj
  sign variants);
- `*_tailConsume_full_core` — the `suffix = full` instances, which are the shapes the
  generated close-pair dispatcher will feed;
- helpers `foldConj_inj`, `foldDisj_inj`, `ground_all_mem_qTailGround_of_eq`,
  `ground_ex_mem_qTailGround_of_eq`, `qTailSigned_mem_qTailBranch`.

Next: assemble the generated close-pair dispatcher (Def 3.66 / Prop 3.67 sources) —
route q-vs-fold source pairs into the `_full_core` entry points; the alignment equation
comes from the generated ground-source inversion. After the dispatcher, attack
Conj 3.50 and then Conj 3.39.
