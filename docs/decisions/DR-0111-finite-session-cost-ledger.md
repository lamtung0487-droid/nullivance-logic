# DR-0111 — Finite continuation sessions and a separate cost ledger

Date: 2026-10-29. Base: `f3c0dc9`. Status: scoped Lean proof checked.

## Claim card

Continue DR-0110's remaining finite-session obligation. Starting with an already
certified stopping result, process an arbitrary finite list of continuation
calls, each carrying a finite list of finite chunks. Preserve the original
first-hit result and consumed count, and accumulate actual new call costs in
a separate ledger. Compose with one initial checkpoint validation, not one
revalidation per call. No axiom or core semantic definition changes.

Candidates to break the claim: no calls; empty calls; a hit followed by more
calls; trusting the arbitrary old cost field; forgetting outer-list inspection
costs; equating the last call's cost with the accumulated cost; and starting
new calls after checkpoint import has failed. An arbitrary finite number of
calls is not an infinite-stream termination claim.

## Executable fold and reference

`runThresholdCalls` returns a renewed consumption certificate and a separate
natural-number ledger. The base returns the existing measured record with
ledger 1 for the terminal call-list inspection. The recursive branch calls
DR-0110's certified continuation, recurses on the remaining calls, and adds
that actual continuation cost plus one call-list cons inspection. It does not
read the input certificate's cost field as a starting balance.

Dependent history indices are reassociated using append associativity only
inside erased proofs. `thresholdCallsData` concatenates the new observations
for specifications; the implementation does not flatten all calls or replay
the old history at runtime. Structural recursion on the call list makes the
function total for supplied finite data. Its returned certificate proves exact
cache/index equality with first-hit stopping on old data followed by all new
observations, and exact consumption of either the tested prefix or the entire
segment on exhaustion.

The scalar soundness corollary retains the same hypotheses: a verified initial
cache and a combined consumed prefix generated by the same scalar state. No
new inference is made from impossible or unauthenticated observation histories.

## Cost ledger

The specification-only `thresholdCallCostSum` follows the same certified state
transitions and sums their actual new call costs. Induction proves that the
returned ledger equals that sum plus K+1, where K is the number of calls. The
extra term prices the session list's K cons inspections and terminal nil.
The specification is not executed as an extra pass by the implementation.

Let N be the total number of new observations, B the total supplied chunk
count across calls, and K the supplied call count. The session ledger satisfies
`ledger <= 5N + 3B + 3K + 1`. This includes DR-0110's per-call dispatch and
inner termination costs, as well as the outer session traversal. If the initial
certificate already contains a hit, its checkpoint fields stay unchanged and
the ledger is exactly `2K+1`: inner data are untested, but each requested call
and its saved-index dispatch still costs work. The fold deliberately processes
the list of requested calls rather than silently deleting later calls.

The certificate's final `cost` field remains the last continuation call's cost
(or the original arbitrary field when there are no calls). It is **not** the
session total; consumers must use the separate ledger. This avoids silently
promoting an uncertified historical report into a verified accumulated cost.
The cost-irrelevance theorem proves that replacing the input certificate's
reported cost with any natural number leaves the new ledger unchanged, even
for zero calls. On the nonempty path the first certified continuation erases
that irrelevant field before any later computation.

For a starting certificate with no hit, K empty calls have no new observations
and no chunks, but cost exactly `3K+1`. This universally quantified boundary
theorem shows why neither observations nor chunk count alone bounds all finite
sessions. Empty calls do not cause progress toward a refutation.

## One checkpoint import, then the session

`importRunThresholdCalls` calls DR-0109's counted checkpoint importer once,
charges one Option dispatch, and starts the session only on success. The joint
specification establishes both its optional certified output and exact counter:
rejection costs I+1; acceptance costs I+1+ledger, where I is the actual import
cost. Thus the whole entry-point upper bound is
`5(Nold+N) + 3(Bold+B) + 3K + 27`.
The accepted-ledger theorem also expands the exact total to
`I + thresholdCallCostSum + K + 2`, making the single initial validation and
both boundary/dispatch contributions explicit.

The result is guarded first-hit reference equality on acceptance and none on
rejection. This does not price validating the supplied initial q against a
separate preceding history, physical sensing, source authentication, parsing,
allocation, stack use, proof work or arithmetic bit complexity. In particular
it is not a wall-clock bound independent of the size of natural-number indices.
Repeated raw checkpoint reimports are not this workflow and would incur extra
validation costs. Finite call counts are explicit; no limit over infinite
sessions or guarantee of an eventual positive recognition is established.

## Boundary regressions

Starting after one silent observation, three calls supply a firing/silent
chunk, no chunks, and a silent chunk. The first call consumes the firing reading
and records the first hit at index 1. Later calls preserve it. The final index
is some 1, consumed count is 2, and session ledger is 14, while the measured
record's final per-call `cost` is only 1. The actual call costs are 8,1,1;
the remaining four units are the three outer cons inspections and terminal nil.
This is a kernel-checked counterexample to interpreting the final per-call
cost as the accumulated ledger.

The one-import entry point for the same case returns
`(some (some 1,2),40)`: import 25, Option dispatch 1, session 14. A checkpoint
with a forged consumed count returns `(none,26)` and starts no calls. These
are kernel-checked regressions supplementing the general theorems.

## Remaining mathematical obligation

Now connect the finite session runner to the eventual-refutation criterion
of DR-0095. Formulate an ordered delivery schedule whose finite delivered
prefix lengths are unbounded, and prove that the finite refutation witness
for a positive scalar intensity is eventually reached by some finite session
prefix. This is an open liveness bridge, not a result proved here. An infinite
sequence of empty calls is an essential counterexample without a progress
hypothesis. Neither an unknown uniform cutoff nor a total decoder follows
from an eventual witness. Zero-intensity neutral states must retain the
earlier finite-refutation limitation.

Checkpoint byte parsing, source authentication and arithmetic bit complexity
also remain separate. This milestone closes finite-session correctness and
the distinct cost-ledger obligation, not unrestricted recognition or the
completeness of the entire logic.
