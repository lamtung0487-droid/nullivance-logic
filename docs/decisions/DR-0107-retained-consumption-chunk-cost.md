# DR-0107 — Retained consumption and repeated-chunk cost

Date: 2026-10-29. Base: `1ac2ec1`. Status: scoped Lean proof checked.

## Claim card

Continue DR-0106's remaining obligation: count consumed observations while
stopping, retain that count, and translate later hit indices without a separate
length scan. The input is an endpoint cache and a finite list of finite chunks
of threshold pairs. The reference is DR-0105's first-hit stop applied to the
flattened sequence. Required conclusions are equality of returned cache and
global first-hit index, exact consumed count, and a cumulative counted bound.
No core definition, semantics or axiom is changed.

Counterexample candidates: empty chunks; arbitrarily many empty chunks;
an initially firing central cache with no new observations; a hit in the first
chunk followed by inconsistent data; a hit at a chunk boundary; confusing total
input size with consumed input size; and using an unchecked external count as
an offset. Exhaustion is still not affirmation of quasivance.

## Algorithm and proof plan

`RecognitionThresholdConsumed.lean` adds a separate measured stopping result
containing cache, optional index, consumed count and operation counter. The
single-chunk runner updates its count as each reading is consumed. The hit
branch counts one; the continuing branch adds one to the recursively retained
count. It neither computes list length nor traverses the unconsumed suffix.

The chunk runner calls that measured stop for the current chunk. On a hit it
returns immediately, without processing remaining chunks. On exhaustion it
continues from the returned cache and uses the returned consumed count to
translate the later index. The consumed counts add. The implementation does
not flatten lists or compute chunk lengths; those appear only in specifications.
The finite input lists are supplied, not generated by a physical observer.

Structural induction on a chunk proves the single runner's output, consumed
count and exact cost jointly. Induction on the list of chunks uses the prior
append/first-hit theorem and the fact that an exhausted chunk's retained count
equals its full length. The result is equivalent for arbitrary supplied data,
without assuming monotonicity. Semantic refutation of a scalar state additionally
requires the earlier realization and schedule hypotheses.

`CertifiedThresholdConsumption` packages the measured result together with
proofs of reference equality and the exact count/index relation. Its constructor
executes the measured chunk runner once; the unoptimized reference occurs in
the erased proof, not as a second runtime pass. `consumedThresholdEndpoint`
accepts an already stored certificate and an already verified initial cache.
It returns the identical final cache, certified for exactly the old history
plus the consumed prefix. No replay occurs during this conversion. A separate
soundness theorem transfers the existing scalar nonquasivance conclusion when
the consumed history really is the specified state's generated threshold prefix.
Neither a raw untrusted counter nor a raw arbitrary cache is such a certificate.
The subtype certifies cache/index and consumed count, not its arbitrary `cost`
field. Cost theorems apply to the actual measured runner (and therefore its
constructor's erasure), not to any externally supplied reported cost.

## Cost units and limits

As in DR-0105, consuming one observation costs five modeled units: update/read
three, input cons inspection one and Boolean branch one. The exhausted inner
list's nil costs one. At the outer chunk level, a cons inspection and Option
dispatch cost two; an exhausted outer list's nil costs one. Arithmetic on
natural-number offsets and counts, record construction, proofs, allocation,
stack behavior, parsing, network/file I/O and measurement are not counted.
In particular this is not a constant-bit-cost claim for unbounded counts.

For one chunk the cost is exactly `5 * consumed + 0` after a hit and
`5 * consumed + 1` after exhaustion. This agrees with the prior stop counter;
retaining the count introduces no additional list inspections in this model.
For B supplied chunks and C consumed observations, the cumulative bound is
`5*C + 3*B + 1`, hence also `5*N + 3*B + 1` for total supplied length N.
The chunk term cannot be dropped: empty chunks still incur inspections.
These bounds include unvisited chunks only on the right-hand side; the runner
does not inspect them once a hit is found. They do not price constructing
the flattened reference list, which is not executed by the implementation.

When every chunk exhausts, the bound `5*N + 3*B + 1` is an equality, proved by
induction with the exhausted-index hypothesis. In particular B empty chunks
have no consumed readings but cost exactly `3*B+1`; a bound depending only on
the number of observations cannot bound arbitrary finite chunking.

The old two-chunk runner remains unchanged for reproducibility. This new
runner removes its separate exhausted-chunk length scan; the boundary/dispatch
overhead remains. No universal wall-time improvement or optimality is claimed.
Indeed a kernel-checked counterexample shows the generic chunk runner costing
15 where the old dedicated two-chunk entry point costs 14: one silent reading
in the first chunk, then a firing reading followed by a silent one. The saved
length scan is smaller there than the new generic outer-list traversal cost.
These are different entry points with explicitly different dispatch accounting.
Removing a scan must not be misreported as every input becoming cheaper.

## Boundary checks

Kernel regressions cover no chunks, one and two empty chunks, a hit in a later
chunk, a first-chunk hit with unvisited trailing chunks, and empty chunks before
the hit. The respective `(index,consumed,cost)` results are
`(none,0,1)`, `(none,0,4)`, `(none,0,7)`, `(some 1,2,15)`,
`(some 1,2,12)`, `(some 1,2,21)`. An initially firing central cache followed
only by empty chunks still returns no hit: the reference tests only after new
readings. Exhaustion does not say the old cache was false, nor imply quasivance.

## Remaining obligation

Compose the new chunk runner with checked external-cache import once, proving
accepted/rejected erasure and the cumulative entry-point cost rather than
assuming it from the previous single-chunk importer. Subsequently, inter-call
serialized checkpoints containing offsets will need their own validation;
the proof-bearing in-memory value here does not authenticate serialized bytes
or source observations. A count supplied from outside cannot be silently
promoted to the verified consumed count.

This milestone closes only the retained-count and finite repeated-chunk
obligation. It proves neither total finite recognition of quasivance nor
termination on an infinite chunk stream. DR-0092's finite-observation
obstruction is unchanged. Nor does it establish a constant-space implementation
or a bit-complexity bound for the growing offset.
